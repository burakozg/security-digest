Recipients

Who receives this instance's digests. One digest is built per recipient, containing the topics addressed to them below plus every topic set to All recipients. Stored in data/users.yaml and edited here — there is nothing to deploy and nothing to keep in sync. A recipient with no topics gets no email at all rather than an empty one. A weekly recipient's topics are still gathered on every run — their items are held and sent as one consolidated edition on their day, carrying the week's key and notable stories.

Topics

Entities tracked by news search (Google News + Bing News). Stored in data/topics.yaml and edited here — there is nothing to deploy and nothing to keep in sync. Each digest in config.yaml lists topic names that must match the names here — the Digests column is read-only and shows which digests pick each topic up; a topic showing “—” reaches nobody. Context is what the model uses to reject same-name-different-subject results, so it is worth writing carefully.

RSS sources

Feeds are saved to data/sources_overrides.yaml so sources.yaml can stay read-only. The initial list still comes from sources.yaml until you save here (then overrides replace the full RSS list). Feeds reach all digests by default — which digest an item actually lands in is decided by its subject area, not by the feed. Use the Digests column only to bar a feed from somewhere; anything you bar is discarded rather than redirected, so the routing table below shows the result.

Status is what the last run actually got from each feed, not a live probe — so it costs nothing and it reports what the digest experienced. Quiet means the feed fetches perfectly well but has published nothing in three weeks, which is how a shut-down publisher looks: no error anywhere, and no items either. Use Check for a feed you have just added or fixed, where waiting for tomorrow's run is no use.

Routing table

Where an item ends up, given the feed it came from and its value. Delivery needs every filter to match, so what matters is the combination — a combination reaching nowhere is summarised at full cost and then discarded. While no feed is barred from anywhere the answer is the same for every feed, so it is shown once; bar a feed in Digests above and the per-feed grid appears. Updates automatically when you save sources.

Flush seen database

Clear the seen link store so previously processed items can be included again in the next run.

AI prompts

Edit the prompts used for categorisation and digest generation. The values below are enforced on the model's answer by the API, and set in config.yaml — a prompt that teaches a different name will have its answers silently replaced by the fallback, so change both together.
